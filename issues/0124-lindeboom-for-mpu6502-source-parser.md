---
title: Write the Nim mpu6502's source parser as a lindeboom grammar
status: open
priority: low
labels: cleanup
---

`mpu6502/src/mpu6502/source_parser.nim` is a hand-written recursive-descent parser, a straight port of the Java `SourceParser` ([0059](0059-convert-to-nim.md), step 1). Deflower's `.flo` parser is generated by lindeboom from `src/deflower/flo/flo.ldb` ([0126](0126-flo-grammar-with-lindeboom.md)), so the assembler's syntax could be a lindeboom grammar too: one way of parsing in the project, and a grammar that can be read as a description of the syntax, which the doc comment at the top of `source_parser.nim` now gives in words. As with `flo.ldb`, the grammar holds no code; a separate walk over the parse tree builds the values.

What has to stay the same:
- **The error messages, word for word.** Deflower prints them (`verifier`) and the snippets' round trip depends on them. Most quote the rest of the line: `expected a value at '+'`, `unexpected '2'`, `expected a name at '1abc'`. The parser's error formatter hook (as `flo_reader.describe` uses it) and the walk over the tree have to produce them. The tests in `mpu6502/tests/test_source_parser.nim` check most of them; add any that are missing before the change.
- **What gets parsed.** The rules that aren't plain grammar have to come along, in the grammar or in the walk: a name at the start of a line is a label unless it is a mnemonic, `asl a` versus an operand named `a`, `@w` only before white space, `'c'` literals and `;` inside strings, the zero page or absolute choice, the `.enc` state, and Java's idea of white space, letters and digits on Unicode characters.
- **The lazy values.** The parser builds `Value` closures that look symbols up later, so forward references keep working. Only the parsing changes, not `assembler.nim`.

The generated parser and lindeboom's runtime are committed as standalone files, as in deflower (`nimble flo`), so mpu6502 gains no dependency, and a test checks they match a fresh generation. mpu6502 must still import nothing of deflower's, so it gets its own copy of the runtime and its own generate task.

Check first whether it pays off: the parser is line-based and small (about 570 lines), and the messages and the context-dependent rules may need as much code around the grammar as the hand-written version has now. If it doesn't get shorter or clearer, close this as rejected.

Done when `source_parser.nim` is replaced by a lindeboom grammar and its walk, `nimble test` in `mpu6502/` passes unchanged, and the Java and Nim versions still assemble the snippets' sources and outputs to the same segments or messages (the cross-check from 0059 step 1).

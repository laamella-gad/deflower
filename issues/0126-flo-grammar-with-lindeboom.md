`flo_reader` reads the `.flo` format with two npeg grammars, a lexer and a statement grammar, plus `build`/`buildLine`/`readParameter`/`readSize` that walk the tokens of an accepted line. The format is only readable as a whole in `README.md`, and the grammar in the code is npeg's notation, mixed with token kinds.

Want: the format as a BNF-style grammar file, the specification of the syntax, from which the lexer and parser are generated. [lindeboom](../../nim_parser_generator) (`/home/danny/IdeaProjects/nim_parser_generator`) does that: an ANTLR 4-style `.ldb` grammar without actions, generated plain Nim lexer and recursive descent parser, a generic parse tree, and error recovery, so one error per bad line as now.

A first try (2026-10-15) parses all 19 `.flo` files in `tests/resources/` and `src/deflower/includes/`:

```antlr
// The .flo format: one statement per line.
grammar Flo;

file        : statement* EOF ;
statement   : COMMENT? NL                                    # blank
            | 'deflower' file=ID NL                          # deflower
            | 'include' file=ID NL                           # include
            | '}' NL                                         # endBlock
            | annotation NL                                  # line
            ;
annotation  : at=place virtual='virtual'? banked='banked'? selfmod='selfmod'?
              type=dataType? name=ID? parameters? noreturn='noreturn'?
              ('export' exportFile=ID)? open='{'? ;
place       : start=number ('-' end=number)? ;
number      : INT | HEX ;
dataType    : typeName ('[' size? ']')? ;
typeName    : 'screencode' | 'ascii' | 'byte' | 'word' | 'long' | 'dword'
            | 'addr' | 'rta' | 'sbyte' | 'sword' | 'slong' | 'sdword' | 'code' ;
size        : 'until' terminator=number                      # until
            | 'lengthbyte'                                   # lengthByte
            | number (op=('*' | '+') number)*                # count
            ;
parameters  : '(' parameter (',' parameter)* ')' ;
parameter   : dataType name=ID? ;

HEX     : '$' [0-9a-fA-F]+ ;
INT     : [0-9]+ ;
ID      : [A-Za-z0-9._?]+ ;
COMMENT : [;#] ~[\r\n]* ;
NL      : [\r\n]+ ;
WS      : [ \t]+ -> skip ;
```

The syntax errors are worse than now, which blocks the switch:

| line | now | lindeboom |
|---|---|---|
| `$c000 byte byte` | `expected a size, a label, export, '{' or the end of the line, found 'byte'` | `expected NL but found 'byte'` |
| `$c000 byte foo bar` | `expected export, '{' or the end of the line, found 'bar'` | `expected NL but found ID` |
| `$c000 @ x` | `unexpected '@'` | `unexpected character '@'` |
| last line without a newline | accepted | `expected NL but found end of input` |

Blocked by lindeboom's issues 13 (skipped optional elements missing from "expected") and 14 (syntax errors as data, with a formatter hook, as ANTLR's error listeners do; it took in issue 15, the found token's text). Its issue 16 (`label` can't be an element label) only forces `name=` in place of `label=`.

The token names stay out of the grammar, which is plain ANTLR: `flo_reader` gives the parser a formatter that names the token kinds (`NL` as `the end of the line`, `ID` as `a label` or `a file name`, `'['` as `a size`) and words the message as now, `line N: expected <parts>, found <token>`.

The plan:
- `src/deflower/flo.ldb` holds the grammar; `README.md` shows it as the syntax summary, next to the prose.
- The generated `flo_lexer.nim` and `flo_parser.nim` are committed, with the runtime (`lindeboom gen --standalone`), so building deflower doesn't need lindeboom.
- A builder walks the parse tree into the `Statement`s (`case n.kind`), in place of `build`/`buildLine`/`readParameter`/`readSize`. The grammar holds no code, as now. Blocks, includes, comment attachment and the checks the grammar can't make stay in `flo_reader`.
- npeg is no longer needed.

## To decide

- **The error format.** Keep deflower's `Failed to parse <file>:` and `line N: <message>` lines, made by the formatter, so the `short/invalid/` snippets stay as they are; or take lindeboom's `file:line:col: error: message`, which changes them all.
- **Regenerating.** A nimble task, `./deflower` rebuilding the parser when `flo.ldb` is newer, or by hand with a test that fails when the committed parser is older than the grammar.
- **The missing final newline.** Append one before parsing, or let the grammar end a statement at `EOF`.

Done when: `flo_reader` uses the parser generated from `flo.ldb`, all snippets pass with the error messages as clear as now (worded by deflower's formatter), npeg is gone from `deflower.nimble`, and `README.md` and `CLAUDE.md` describe the grammar file and how to regenerate the parser.

Related: [0125](0125-command-line-parser-library.md) (the command line), [0124](0124-npeg-for-mpu6502-source-parser.md) (mpu6502's source parser as npeg, which this may change).

## Decisions

- **Unblocked** (2026-10-15): lindeboom's issues 13, 14 and 16 are done. `$c000 byte byte` now gives `expected 'noreturn', 'export', '{', '[', '(', ID or NL but found 'byte'`, and parsers take a `formatter` that gets the found token and the expected kinds as data.
- **The error format stays deflower's**: `Failed to parse <file>:`, then `line N: expected <parts>, found <token>`, worded by deflower's formatter. The `short/invalid/` snippets change only where the expected lists get more complete.
- **A standalone copy, until lindeboom is released as a package**: `lindeboom gen --standalone` output, the generated lexer and parser and the runtime, is committed in deflower, so building deflower doesn't need lindeboom.
- **Regenerating**: a nimble task regenerates the parser from `flo.ldb`, and a test fails when the committed parser differs from a fresh generation (skipped when lindeboom isn't there).

## Closing note

Done 2026-10-15. The grammar is `src/deflower/flo/flo.ldb` (the first try above, with `label=`, and the flag keywords unlabelled: `build` finds them with the runtime's `has`, lindeboom's issue 18), and `nimble flo` builds lindeboom from `LINDEBOOM_SRC` (default `../nim_parser_generator`) and regenerates `flo_lexer.nim`, `flo_parser.nim` and `lindeboom_runtime/` next to it, all committed. `flo_reader` calls `parseFile`, `build` turns each statement node into a `Statement`, and `describe`, the formatter, words the errors as before: the type keywords as `a type`, `'['` as `a size`, `ID` as `a label` or `a file name`, numbers as `an address` or `a number`, `NL` as `the end of the line`, parameters and `noreturn` only on a code line, in the order of a line. The first error of each line by position is kept. The missing final newline is still appended in `collect`.

Three `short/invalid/` snippets changed, all one more expected part: `'-'` after a line's start address (`two-addresses`, `top-level-plus`, `top-level-multiplier`), where a range end is valid. npeg is gone from `deflower.nimble`; deflower builds with Nim alone.

`tests/test_flo_parser.nim` regenerates into a temporary directory and compares (skipped without lindeboom's sources), and checks that `README.md`'s new "The grammar" section holds the grammar.
